# Проверка без сети: как и зачем

Заявление «тесты проходят без сети» проверяемо только в окружении, где сети нет
целиком. Блокировка сокетов внутри одного процесса её не заменяет: подпроцесс
(`broken_refs.py`, запускаемый тестом) наследует блокировку лишь тогда, когда она
передана через окружение, а раньше не передавалась — и шаг «без сети» в CI
проходил, ничего не доказывая.

## Как запускать

Локально, без root, через bubblewrap:

```bash
bwrap --bind / / --dev /dev --proc /proc --unshare-net \
  --chdir "$PWD" env PYTHONDONTWRITEBYTECODE=1 \
  python3 -B tests/run_offline.py
```

В CI — контейнер без сети:

```bash
docker run --rm --network none -v "$PWD":/w -w /w python:3.12 \
  python3 -B tests/run_offline.py
```

Ожидаемый результат в обоих случаях: `0 провалено`, и отдельно
`python3 scripts/broken_refs.py --strict-own` завершается с кодом 0.

## Что делает сам репозиторий

- `tests/run_offline.py` выставляет подпроцессам `VH_OFFLINE=1` и
  `VH_UPSTREAM_TREES=tests/fixtures/upstream-trees.json.gz` — снимок деревьев
  апстримов (путь → blob sha) на момент сборки.
- Скрипты при `VH_OFFLINE=1` в сеть не обращаются вовсе, а деревья берут из
  фикстуры: числа классификации при этом совпадают с сетевым прогоном.
- `broken_refs.py --strict-own` проверяет собственные навыки ДО обращения к API:
  для этой проверки апстримы не нужны, и код выхода от сети не зависит.

## Почему это важно именно здесь

Отчёт `docs/broken-refs.md` — источник чисел для README. Без деревьев апстримов
часть категорий («в корне источника», «тяжёлые») посчиталась бы нулём, а
«унаследованное» выросло бы за счёт разобранного: 227 → 311 при том же итоге 492.
Валидатор сверял только итог и такое пропускал. Поэтому скрипт в офлайне не
перезаписывает отчёт, а завершается с кодом 2 — молча испортить числа он не может.
