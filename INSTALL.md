# Установка и использование

Что за репозиторий, как им пользоваться, что чем закрывается. Для того, кто
берёт библиотеку себе, а не читает её исходники.

## Что это

Vector Health — **библиотека медицинских и биомедицинских навыков**, а не
программа и не медицинский сервис. Внутри три слоя:

1. **1541 навык** — каталоги `skills/<имя>/SKILL.md` с вспомогательными
   `references/`, `scripts/`, `assets/`. Работают без установки: это markdown,
   который читает агент (Hermes, OpenClaw, Claude Code, Codex и любая
   SKILL.md-совместимая платформа).
2. **Каталог для поиска** — `skills-index.json`: имя, путь и описание каждого
   навыка. Нужен потому, что 1541 описаний в системном промпте — лишний контекст,
   а поиск по каталогу — нет.
3. **Скрипты обслуживания** — `scripts/` (синхронизация с апстримами, сборка
   каталога, проверки). Только стандартная библиотека Python.

Готового агента-врача здесь нет и не планируется: репозиторий поставляет
**методики и справочники**, а не диагнозы.

## Требования

- **Для библиотеки** — ничего, кроме возможности читать markdown.
- **Для скриптов** — Python 3.11+ и стандартная библиотека. Внешних зависимостей
  нет намеренно: скрипты должны запускаться на чистом раннере.
- **Для синхронизации с апстримами** — токен GitHub. Скрипты читают его в порядке:
  `GITHUB_TOKEN`, затем `GH_TOKEN` (так переменную называет GitHub Actions), затем
  `gh auth token`, затем `~/.hermes/.env`. Порядок единый для всех скриптов
  (`refs.github_token`): раньше токен брался только из `gh`, и обещание читать
  переменную окружения не выполнялось — в CI запросы шли анонимно и упирались в
  лимит 60 запросов в час. Без токена `broken_refs.py` не перезаписывает отчёт
  деградировавшими числами, а завершается с кодом 2.
- **Для диаграммы** — Node 18+ и `archify` (Apache-независимый проект под MIT).
  Пакет в npm не публикуется, ставится из репозитория по пришпиленному тегу:

  ```bash
  bash scripts/install-archify.sh archify     # по умолчанию v2.16.0
  ARCHIFY_VERSION=v2.17.0 bash scripts/install-archify.sh archify   # другая версия
  ```

  Скрипт сам проверяет себя командой `doctor` и падает, если раскладка пакета
  изменилась. В CI archify устанавливается всегда — проверка диаграммы больше не
  пропускается.
- **Для навыка `dicom-vlm-analysis`** — `pydicom` (рендер с window/level, чистый
  Python) и локальная [Ollama](https://ollama.com) с моделью `medgemma:4b`. Без
  Ollama навык бесполезен: он описывает снимок локальной моделью, а не облачной.
  Веса модели скачиваются отдельно, в репозиторий не входят.
- **Для навыка `abdominal-ct-findings`** — ничего: это таблицы и JSON.
  Модель RADAR, из которой взята таксономия, не требуется и не поддерживается
  на этом железе (её веса к тому же под некоммерческой лицензией).

## Быстрый старт

```bash
git clone https://github.com/Osmosy/vector-health.git
cd vector-health
```

### 1. Найти навык

```bash
# по каталогу: имя, путь, описание
python3 -c "
import json
d = json.load(open('skills-index.json'))
for s in d['skills']:
    if 'dicom' in s['name'] or 'abdominal' in s['name']:
        print(s['path'], '—', s['description'][:90])
"

# или просто глазами
ls skills | grep -i dicom
less skills/dicom-vlm-analysis/SKILL.md
```

### 2. Подключить к своему агенту

Навык — это каталог с `SKILL.md`. Скопируйте нужный каталог целиком (вместе с
`references/` и `scripts/` — на них ссылается текст) в место, откуда ваш агент
читает навыки:

```bash
# Hermes Agent
cp -r skills/dicom-vlm-analysis ~/.hermes/skills/

# любой другой агент — туда, где он ищет SKILL.md
```

Ставить все 1541 сразу не нужно и не рекомендуется: каталог существует ровно
затем, чтобы брать по надобности.

### 3. Проверить целостность (если правите)

```bash
python3 scripts/validate.py            # всё: 27 проверок — числа, лицензии, ссылки, диаграмма
python3 scripts/build_stats.py         # пересобрать единый источник чисел (stats.json)
python3 scripts/plant_sibling_files.py --apply   # разложить копии общих файлов апстрима
python3 scripts/broken_refs.py         # ссылки внутри навыков (инвентарь)
python3 scripts/sync_upstreams.py --dry-run   # что изменилось в апстримах
```

## Что чем закрывается

| Задача | Чем |
|---|---|
| «Есть ли навык под DICOM/радиомику?» | `skills-index.json` или `ls skills \| grep` |
| «Как читать КТ/МРТ локальной моделью?» | `skills/dicom-vlm-analysis/SKILL.md` (нужны `pydicom`, локальная Ollama и модель `medgemma:4b` — см. раздел ниже) |
| «Мета-анализ: как считать?» | `skills/meta-analysis/SKILL.md` + `references/` (4 скрипта лежат в корне репозитория-источника, а не в каталоге навыка — ссылки и способ взять файл в `docs/broken-refs.md`) |
| «Что нового в апстримах?» | `python3 scripts/sync_upstreams.py --dry-run` |
| «Почему ссылка в навыке битая?» | `docs/broken-refs.md` — инвентарь из девяти категорий (497 ссылок): 81 внешних ресурсов, 80 есть у соседнего навыка, 73 апстрим не публиковал, 11 путь разошёлся — и остальное с причиной и местом, откуда ресурс берётся |
| «Откуда этот навык пришёл?» | `scripts/upstream-origin.json`, `NOTICE.md` |

## Обновление и проверки

Навыки обновляются из четырёх источников скриптом:

```bash
python3 scripts/sync_upstreams.py --dry-run          # только показать план
python3 scripts/sync_upstreams.py                    # применить
python3 scripts/sync_upstreams.py --only openmed     # один источник
python3 scripts/build_index.py                       # пересобрать каталог
```

Скрипт идемпотентен: повторный запуск без изменений в апстриме печатает
`обновить 0, добавить 0, удалить 0`. Это и есть проверка, что синхронизация
завершена, — а не сообщение о том, что она запускалась.

Перед коммитом — те же проверки, что выполняет CI:

```bash
python3 scripts/validate.py
python3 scripts/broken_refs.py --strict-own
python3 tests/test_scripts.py
```

## Ограничения

### Лицензии вендоренных навыков

MIT репозитория покрывает **собственный вклад**. У части вендоренных навыков лицензия
ограничивает использование, и это надо знать ДО работы с ними (полная таблица и
разбор — `NOTICE.md`):

| Что | Навыков | Следствие |
|---|---|---|
| Проприетарная шапка в тексте навыка («proprietary and confidential… All Rights Reserved», © MD BABU MIA — из апстрима OpenClaw) | 308 | считать MIT нельзя |
| Офисные навыки Anthropic (`PPTX-Skill`, `docx`, `docx-official`, `pdf`, `pdf-anthropic`, `pptx`, `pptx-official`, `xlsx`, `xlsx-official`) | 9 | «© 2025 Anthropic, PBC. All rights reserved» |
| `Non-Commercial` | 2 | коммерческое использование запрещено. Это **один навык в двух местах** — `varcadd-pathogenicity` и `variant-interpretation-acmg/varCADD` (одинаковый sha); он же входит в первое ограничение списка |
| **Итого уникальных навыков с ограничениями** | **317** | сумма по видам (308 + 9 + 2) даёт 319: **два «Non-Commercial» — это один навык** `varCADD` в двух местах (один sha), и он же входит в первое ограничение списка |
| Таксономия RADAR в `abdominal-ct-findings` | 1 | текст — Apache-2.0 (ок), но **веса модели — CC BY-NC-SA 4.0** и не берутся |

Перед использованием конкретного навыка проверьте его поле `license` и первые строки
`SKILL.md`. Числа сверяются с деревом: `python3 scripts/validate.py`.


- **Библиотека — не медицинское изделие.** Навыки описывают методики; ни один
  вывод не является диагнозом, назначением или заключением. Ответственность за
  клиническое решение — на квалифицированном специалисте.
- **Тексты навыков на языке источника.** Китайские и английские навыки не
  переводились: перевод 1541 текстов разошёлся бы с апстримом и сделал бы
  синхронизацию невозможной. Русский — только собственная документация.
- **Часть ссылок внутри навыков битая** — унаследовано от апстримов (файлы
  нет ни в HEAD источника, ни в истории — либо не закоммичены, либо лежали в служебном каталоге, убранном при сборке). Инвентарь:
  `docs/broken-refs.md`; у собственных навыков битых ссылок нет, это проверяет CI.
- **Вложенные навыки** (28 из 1541) лежат внутри каталогов-контейнеров — это
  структура апстримов, а не ошибка сборки; в каталоге их видно по полю `path`.
- **Лицензия OpenClaw-Medical-Skills** заявлена только в README, файла нет —
  подробности и практический вывод в `NOTICE.md`.
- **Синхронизация требует сети и токена GitHub.** Без них библиотека работает,
  обновляться — нет.

## Где что менять

- Навыки — `skills/` **только через** `scripts/sync_upstreams.py`. Правка
  вендоренного текста руками будет затёрта следующей синхронизацией, и это
  ожидаемое поведение, а не потеря работы.
- Собственные навыки — `skills/dicom-vlm-analysis`,
  `skills/atrial-fibrillation-treatment`: их можно править напрямую, синхронизация
  их не трогает.
- Каталог — `skills-index.json` генерируется: `scripts/build_index.py`.
- Документация — `README.md`, `NOTICE.md`, `INSTALL.md`, `AGENTS.md`, `docs/`;
  числа и оговорки проверяет `scripts/validate.py`, поэтому правьте документ и
  проверку вместе.
- Диаграмма — `docs/vector-health.architecture.json` (спецификация). Правьте
  спецификацию, затем пересоберите артефакт: `node archify/bin/archify.mjs deliver
  architecture docs/vector-health.architecture.json docs/vector-health.architecture.html
  --quality showcase`. CI проверяет, что HTML воспроизводится из спецификации
  (`scripts/check_diagram.py`), поэтому правка одного файла без другого роняет сборку.
- CI — `.github/workflows/validate.yml`.
