# Как мерить качество модели на медицинских изображениях — и как не обмануться

Методика, разобранная по первоисточникам на примере открытой модели RADAR
(Alibaba DAMO Academy, Science 2026). Здесь нет «правильных выводов про RADAR» —
здесь то, что применимо к **любой** модели такого класса, и на чём ловятся
завышенные цифры.

## 1. Одно число AUC не описывает модель — оно описывает лучший из её сценариев

В статье про RADAR приведён целый набор AUC, и они отличаются принципиально:

| Что замерялось | AUC | Смысл |
|---|---|---|
| Внутренняя когорта, 39 160 обследований, 146 находок | **0.913** (95% ДИ 0.911–0.915) | та цифра, которую цитируют в промо |
| Восемь внешних центров | 0.874–0.912 | разброс между центрами |
| Другая популяция, без дообучения | 0.883 | перенос на незнакомые данные |
| Острые состояния (исключены из обучения) | 0.904 | генерализация на незнакомое |
| Четыре вида рака, подтверждение по патоморфологии | 0.891–0.984 | самый узкий и самый точный случай |

Практический вывод: **всегда спрашивайте, на какой когорте считано среднее**, и
считайте «внутренняя / внешняя / без дообучения» тремя разными числами. Разница
0.913 и 0.883 — это разница между «работает на наших данных» и «работает на
чужих», и именно она решает вопрос внедрения.

## 2. Среднее по 146 классам скрывает провалы — смотрите худшие, не лучшие

Опубликованный вывод модели на внешнем тесте MERLIN (`docs/INFERENCE.md` в
репозитории) со средним **AvgAUC 0.8835** содержит разброс от 0.683 до 0.990:

| Находка | AUC | Комментарий |
|---|---|---|
| Аневризма брюшной аорты | 0.9903 | лучший класс |
| Кишечная непроходимость | 0.9704 | |
| Спленомегалия | 0.9682 | размерная характеристика — простая |
| Плевральный выпот | 0.9574 | |
| Атрофия поджелудочной железы | 0.9356 | |
| Камни желчного пузыря | 0.9193 | |
| Гиподенсные очаги почек | 0.9122 | |
| Гиподенсные очаги печени | 0.8917 | |
| Атеросклероз | 0.8739 | |
| Внутрипечёночное расширение желчных протоков | 0.8711 | |
| Ателектаз | **0.7091** | слабый класс |
| Перелом | **0.6834** | слабый класс |

Слабые классы в среднем незаметны: 0.8835 выглядит ровно, хотя перелом
распознаётся на уровне, близком к случайному угадыванию при дисбалансе классов.
**Правило: в отчёте — строка на каждый класс; одна строка со средним — не отчёт.**

Дополнительно смотрите, какие классы — «простые» (объём органа, кальцинат,
наличие/отсутствие) и какие — «сложные» (перелом, ателектаз, очаговые изменения).
Высокий средний AUC часто набран простыми классами, которых в списке большинство.

## 3. AUC — это не точность и не пригодность к работе

AUC 0.913 означает: случайно выбранный положительный пример получает балл выше
случайно выбранного отрицательного в 91.3% случаев. Это **ранжирующая** метрика.
Следствия, которые надо проговаривать:

- Нет порога — значит, нет ответа «сколько пропусков и сколько ложных тревог» на
  конкретном рабочем пороге. Для клиники важнее sensitivity при фиксированном
  уровне ложных срабатываний.
- AUC устойчива к дисбалансу классов, поэтому выглядит хорошо там, где
  precision низкая.
- «Превзошла 23 из 26 рентгенологов» — это про согласие с разметкой, а не про
  исходы. Ни одна AUC не говорит, улучшилось ли самочувствие пациента.

Что запрашивать вместо AUC (или вместе с ним): sensitivity/specificity на рабочем
пороге, калибровку предсказанных вероятностей, число пропусков на 1000
исследований, и только потом сравнение с врачом.

## 4. Замер с участием врачей: что именно сравнивали

В исследовании RADAR 26 рентгенологов из 14 центров читали одни и те же случаи
с моделью и без. Результат: помощь модели подняла **чувствительность** группы
примерно на 10%, то есть уменьшила число пропусков. Важные уточнения, без
которых цифра вводит в заблуждение:

- речь о **чувствительности** (пропуски), а не о специфичности и не об общей
  точности: рост чувствительности при чтении с подсказкой нередко покупается
  ложными срабатываниями, и это надо смотреть отдельно;
- сравнение шло с разметкой по данным, а не с исходами лечения;
- «точность выше 23 из 26 участников» относится **к этой выборке врачей и этих
  случаев**; переносить на «любого рентгенолога» нельзя.

## 5. Что проверять в репозитории модели, прежде чем верить цифрам

Порядок, отработанный на RADAR (каждый пункт ловит свой класс ошибок):

1. **Воспроизводимый ли вывод.** В репозитории RADAR лежит `calc_metrics_merlin_testset.py`
   и CSV с предсказаниями — цифры можно пересчитать. Таблица в README без входа —
   заявление, а не доказательство.
2. **Совпадает ли число классов с заявленным.** Пересчитайте заголовок CSV:
   146 находок × 18 органов — считайте машиной, а не глазами.
3. **На чём обучено против того, на чём замерено.** У RADAR обучающая выборка —
   424 911 обследований, а опубликованное «почти 40 000» — тестовая когорта.
   Промо такие пары путает, и разница бывает десятикратной.
4. **Какое из чисел цитируют.** Обычно берут максимальное (внутренняя когорта) и
   называют его «точностью модели», опуская внешние.
5. **Лицензию — по каждому артефакту отдельно.** У RADAR: код Apache-2.0, веса на
   HuggingFace CC BY-NC-SA 4.0 (некоммерческая), запись в Zenodo CC-BY-4.0 — три
   разные лицензии у одного проекта, и связывающая руки не та, что в разделе
   License основного README.

## 6. Оговорки о данных и железе, которые надо выяснить заранее

- **Железо.** Модель обучали на 24 GPU (A100/H20), инференс документирован под
  A100 или H20, а в коде device зашит прямыми вызовами `.cuda()`. Это не
  «работает везде»: для не-NVIDIA нужен патч (в репозитории есть issue об этом).
- **Модальность.** RADAR читает только КТ брюшной полости с контрастированием —
  ни анализов, ни рентгена, ни УЗИ, ни КТ без контраста в заявленных
  возможностях нет.
- **Данные пациентов.** В RADAR в git лежат реальные КТ-обследования (порядка
  340 МБ) и CSV с предсказаниями. В статье сказано, что данные деидентифицированы
  и получены с одобрения IRB, но **в самих документах репозитория слов
  de-identified / anonymized / IRB / consent нет** — при переносе куда-либо это
  надо выяснить отдельно, а не предполагать.

## 7. Форма отчёта о качестве модели (шаблон)

```
Модель: <название, версия/чекпоинт>
Модальность и область: <что подаётся на вход, что НЕ подаётся>
Когорты замера (раздельно):
  внутренняя   N=<...>  AUC=<...> (ДИ)
  внешняя      N=<...>  AUC=<...>  разброс по центрам <...–...>
  без дообучения N=<...> AUC=<...>
Разборы по классам: таблица «класс → AUC → N → комментарий», лучший и худший обязательно
Порог: sensitivity=<...> specificity=<...> на выбранном рабочем пороге
Пропуски: <N> на 1000 исследований
Сравнение с врачом: тип выборки, число участников, что именно сравнивали (чувствительность/точность/согласие)
Лицензии по артефактам: код <...> веса <...> данные <...>
Железо и зависимости: <...>
Оговорки: чего модель не делает; что не проверено
```

Пункт «чего модель не делает» и «что не проверено» — не вежливость, а самая
полезная часть отчёта: именно там промо и реальность расходятся сильнее всего.
